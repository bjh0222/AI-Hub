## 2. 需求拆解：我真正要解决的问题

**表层需求**：把六个 AI 网页放进一个页面。

**真实痛点**（决定了功能优先级）：

1. **切换成本**：每次找某个 AI 要在书签/历史/地址栏里翻 → 核心解法是「一屏六入口 + 搜索直达」
2. **常用模型反复找** → 收藏置顶
3. **同一个问题想同时问几个模型** → 一键多开（且必须保证可达，不能假成功）
4. **刚用过哪个、用了几次记不住** → 最近使用记录
5. **不想让别人乱点** → 访问保护

**成功判据**：从打开页面到「目标模型开始加载」≤ 2 次操作（含 1 次点击）。
任何一次「纠错」（点了没反应、提示打开成功其实没开、链接点不动）都会吃掉当次节省的全部收益 —— 这是全篇设计的判据。

**明确不是需求**：统一对话界面、上下文互通、历史同步、模型对比回答。

## 5. 系统架构与数据流

### 5.1 架构（刻意做到最薄）

```
浏览器 ──► Next.js（单进程，无需独立后端）
              ├─ 服务端：路由组 layout 做鉴权 + 2 个 Route Handler（登录/登出）
              └─ 客户端：React 界面，localStorage 存偏好
                        │
                        └─► 点击卡片 ──► 官方 AI 网页（新标签页，与本站无关）
```

- **没有数据库**：状态无痕，会话用 HMAC 签名令牌自包含。
- **没有独立后端服务**：`next start` 进程本身就是后端。
- **为什么必须有服务端代码**：`httpOnly` Cookie 只能由服务端 `Set-Cookie` 写入。把令牌放进 localStorage 等于把签名密钥送进浏览器，XSS 一键接管 —— 这条不让步。

### 5.2 数据流

| 场景 | 数据流 |
|---|---|
| 登录 | 表单 → `POST /api/auth/login` →（同源校验 → 限流 → scrypt 比较）→ `Set-Cookie: aihub_session=<HMAC 令牌>` → 303/JSON 跳转 |
| 每次进入 | 请求 → `(hub)/layout.tsx` → `await cookies()` → 验签 + 过期 + 指纹 → 通过渲染 / 不过 `redirect('/login')` |
| 打开模型 | 纯浏览器行为：`window.open(官方地址)`；同时把 `{platformId, 时间戳, 次数}` 写进 localStorage |
| 多开 | 同步栈内开 1 个 → 结果与其余链接进入面板 → 点链接同样记录 |
| 备份 | localStorage → JSON 文件下载；导入时经过迁移 + 白名单清洗 |

**隐私红线**：localStorage 里只有 `platformId`、时间戳、次数、开关；**永不写入对话内容、对话 URL、平台 Cookie、搜索关键词**。

### 5.3 访问保护（本项目最关键的技术决策）

| 方案 | 结论 |
|---|---|
| `middleware` / `proxy.ts`（Edge Runtime） | ❌ 不用。Edge 无 `node:crypto`，且 Next 16 起 `middleware` 更名为 `proxy`，两个坑都不踩 |
| **路由组 `(hub)/layout.tsx` + `await cookies()` + `node:crypto`** | ✅ 采用。天然 Node Runtime，官方也建议非必要不用 middleware |
| next-auth / 第三方库 | ❌ 一个密码验证不值得引入一整套依赖与它的升级负担 |

派生关系：`签名密钥 = HMAC(SESSION_SECRET, sha256(密码哈希/明文) 前 32 位)` →
**改密码 = 所有已登录设备立即失效**，不需要任何会话表。代价：不能单独踢掉某一台设备（单人自用，接受）。

**一个容易踩的细节（已处理）**：鉴权 layout 与登录页都**无条件先 `await cookies()`**。
理由：如果只在「配置齐全」的分支里调用动态 API，那么在**没有 `.env.local` 的构建机**上，
配置提示页会被当成静态页面烘焙进产物，部署后即使配好环境变量也永远只看到提示页。
无条件调用动态 API 让整组路由始终动态渲染，从根上避免这类「构建期快照」问题。

## 6. 接口设计

本站只有两个接口，没有「统一模型调用抽象层」——因为不调用模型。

### `POST /api/auth/login`

| 项 | 内容 |
|---|---|
| 请求体 | `application/json`：`{ "password": string, "next": string }`；或 `application/x-www-form-urlencoded`（无 JS 回退） |
| 成功 | `200 { "ok": true, "next": "/" }` + `Set-Cookie`（表单提交则为 `303` → `next`） |
| 失败 | `401 { ok:false, error:"invalid" }`；限流：`429 { error:"locked", retryAfterSeconds }`；跨站：`403 { error:"bad_origin" }`；未配置：`503 { error:"not_configured" }` |
| 校验顺序 | 同源 → 限流 → 递增延迟 → 密码比较 → 签发令牌 |
| 上游限制 | 无（不触达任何第三方） |

### `POST /api/auth/logout`

清空会话 Cookie → `303` 跳 `/login`。用原生 `<form method="post">` 提交，不依赖 JS，也不需要 CSRF token。

### 令牌格式

```
v1.<expEpochSeconds>.<iatEpochSeconds>.<hmacSha256Hex64>
```
校验：格式白名单（数字位长 + 64 位 hex）→ 常量时间比较 → 过期判断 → 未来签发（时钟异常）拒绝。

## 8. 技术选型

| 层面 | 选择 | 适用条件 / 替代方案 |
|---|---|---|
| 框架 | Next.js App Router | 只用基础能力，**兼容 Next 15 与 16**；若想纯静态托管，`output: 'export'` 会**让访问保护失效**，不建议 |
| 语言 | TypeScript `strict` | 单人项目改类型成本几乎为零 |
| 样式 | Tailwind CSS v3 + CSS 变量令牌 | 6 张卡 + 搜索框的量级，手写 CSS 也行；Tailwind 的价值是「不用起名」。**不引 UI 组件库** |
| 密码哈希 | `node:crypto` scrypt（N=16384, r=8, p=1） | 替代：bcrypt/argon2 需要原生编译，Windows 上安装失败率更高，边际安全收益不值 |
| 会话 | 无状态 HMAC 令牌（自研 30 行） | 替代：`jose`（JWT 库，多一个依赖）、服务端会话表（要数据库） |
| 存储 | localStorage（单键 + 版本号 + 白名单清洗） | 替代：SQLite（+2~3 天，换多设备同步 —— 你不需要） |
| 图标 | 内联 SVG | 不引图标库、不用位图，首屏零额外请求 |
| 字体 | 系统字体栈（Windows 优先） | 不用 `next/font` 外链，避免首屏字体请求与 FOUT |
| 测试 | Node 自带类型擦除 + 手写断言器 + 文本级静态自检 | 替代：Vitest（要装依赖）、Playwright（对 6 个链接的站点，维护利息高于收益） |

## 9.5 实测发现（只有真的跑起来才会暴露的两个问题）

这两条是本次交付里最有价值的部分 —— 静态检查、类型检查、单元测试**全都发现不了**它们。

### 发现 1：`$` 被 dotenv 展开，症状是「密码永远错」

- **现象**：部署后输入正确密码，接口固定返回 `401 invalid`。
- **根因**：Next.js 用 `dotenv-expand` 解析 `.env.local`，**值里的 `$` 会被当变量引用展开**。实测对照（同一份配置）：

  | | 内容 | 长度 |
  |---|---|---|
  | 写进 `.env.local` | `scrypt$16384$8$1$L+3TI3+...` | 86 |
  | 进程实际读到的 | `scrypt6384+3TI3+...` | 34 |

  `$16384` → `6384`、`$8`/`$1` → 空串，哈希彻底变了样。
- **修复**：哈希格式从 `scrypt$N$r$p$salt$hash` 改成 **`scrypt:N:r:p:salt:hash`**，且 salt/hash 改用 **base64url**（只含 `A-Za-z0-9-_`，任何 shell、任何 .env 解析器都碰不坏）。旧 `$` 格式仍兼容。
- **防复发**：① 单测里加「哈希串不含 `$`」与「经 @next/env 解析后一字不变」两条回归；② 新增 `npm run check-env`，用**同一套解析器**读一遍并真的验一次密码；③ `setup.ps1` 写完 `.env.local` 后自动跑这个体检，不通过就报错退出。

### 发现 2：`next start` 跑的是构建产物，改代码不重建等于没改

- **现象**：修好哈希格式后重启服务，依然 401。
- **根因**：`npm start` 服务的是上一次 `npm run build` 的输出；我改了源码但没重新构建，服务端还在跑**修好之前**的 `parseHash`（只认 `$` 格式，读到冒号格式直接判为非法）。
- **修复**：改完源码必须 `npm run build` 再 `npm start`；只改观感用 `npm run dev`。
- **防复发**：写进 README §9「常见坑」，并在交付说明里明确这条纪律。

> **测试方法上的教训**：用 PowerShell 调 `curl.exe --data-binary '{"password":"..."}'` 时，引号可能被原生参数传递规则吃掉，服务端收到的是非法 JSON（表现同样是 401）—— 一度让排查方向跑偏。最终换成两种可靠写法：**Node 的 `fetch`**（即 `scripts/e2e.mjs`）或 **`--data-binary "@file.json"`**。测试工具本身出错，比被测代码出错更容易骗过你。
